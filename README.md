# Юридический ассистент ПСБ

Решение кейса ПСБ на Hack&Change 2026. Ассистент отвечает юристам на вопросы по базе
нормативных документов: законам, договорам и внутренним регламентам. Каждый вывод
подтверждается ссылкой на пункт документа. Если в базе нет данных, ассистент так и
говорит. Вывод с числом, пунктом или статьёй, которых нет в документах, до пользователя
не доходит.

Один конвейер обслуживает два входа:
- `solution.py` — автоматическая проверка на платформе;
- `web/` — чат с просмотром документов.

План работ и принятые решения: [PLAN.md](PLAN.md).

## Запуск одной командой

Нужны Docker и Docker Compose 2.24 или новее.

```bash
cp .env.example .env
```

В `.env` укажите `LLM_BASE_URL` и `LLM_API_KEY` (см. «Внешние API»). Затем:

```bash
docker compose up --build
```

Интерфейс откроется на http://localhost:8000. Без ключа интерфейс и просмотр документов
работают, а чат отвечает, что языковая модель недоступна.

## Порядок проверки основного сценария

1. Откройте http://localhost:8000 и нажмите первый пример вопроса — про арендную плату
   по договору с ООО «Северный Склад».
2. Ответ содержит сумму и срок со ссылками на пункты; под ответом плашка «Договор
   аренды А-08-2024 Северный Склад». Справа открыт договор, процитированные пункты
   выделены.
3. Задайте уточнение в том же диалоге, например «А что делать при возврате помещения?».
   Ассистент учитывает предыдущие реплики.
4. Нажмите «Новый диалог» и пример про пособие по беременности и родам: таких
   документов в базе нет, ассистент сообщает об этом и не отвечает по памяти.
5. Пример про договор на 12 млн рублей в августе 2024 года: ответ опирается на
   редакцию регламента, действовавшую на эту дату.
6. Выберите любой документ в списке справа, чтобы прочитать его целиком.

Проверка скрипта платформы — в разделе «Сабмит на платформу».

## Внешние API

| Что | Модель | Переменные |
|---|---|---|
| Генерация ответов | DeepSeek V4.1 Flash | `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` |
| Эмбеддинги (`POST /embeddings`) | BAAI/bge-m3 | тот же адрес и ключ, `EMB_MODEL` |
| Реранкер (`POST /rerank`) | Qwen3 Reranker 8B | тот же адрес и ключ, `RERANKER_MODEL` |

Все три модели вызываются через один OpenAI-совместимый API. На платформе хакатона
адрес, ключ и имена моделей подставляются автоматически. Локально подойдёт любой
провайдер с этими моделями; идентификаторы по умолчанию:
`deepseek/deepseek-v4.1-flash`, `baai/bge-m3`, `qwen/qwen3-reranker-8b`.

Подключение ключа: впишите его в `.env` (файл в `.gitignore`) или передайте переменной
окружения. В коде, образе и репозитории ключей нет, в логи они не пишутся. Если API
эмбеддингов или реранкера недоступен, поиск продолжает работать на TF-IDF.

## Архитектура

```
вопрос (+ история диалога)
  → dialog   разбор реплик «Пользователь:/Ассистент:»
  → search   TF-IDF по символьным n-граммам + bge-m3 → RRF → реранкер; сборка контекста
  → dates    дата события → применимые редакции, изменения норм после этой даты
  → prompts  инструкция + документы как данные
  → LLM
  → guard    числа, пункты, статьи, номера законов ответа есть в документах?
             нет → один повтор с перечнем нарушений → неподтверждённые предложения удаляются
  → ответ (+ citations: какие пункты подсветить в интерфейсе)
```

| Модуль | Назначение |
|---|---|
| `solution.py` | точка входа платформы: `questions.csv` + `knowledge-base.zip` → `submission.csv` |
| `kb.py` | чтение архива (txt, md, docx), разбор на пункты договоров и законов со смещениями в тексте |
| `dialog.py` | разбор истории диалога из текста вопроса |
| `search.py` | гибридный поиск и сборка контекста |
| `relations.py` | связи документов: доп. соглашение ↔ договор, редакции одного регламента |
| `dates.py` | дата события; срок действия редакций; изменения норм после даты события |
| `guard.py` | проверка ответа против переданных модели текстов |
| `prompts.py` | системная инструкция, пометки о редакциях, сборка сообщений |
| `answer.py` | вопрос → ответ с проверкой и одним повтором |
| `citations.py` | какие документы и пункты цитирует ответ |
| `web/app.py`, `web/static/` | HTTP API и чат без сборки фронтенда |
| `llm.py` | запросы к API с повторами на 429/5xx/таймаут |
| `config.py` | переменные окружения |

Контекст модели:
- документы до 6 000 символов модель получает целиком, у крупных — найденные пункты
  и оглавление статьи (начало каждого пункта);
- вместе с договором идут его дополнительные соглашения, вместе с регламентом — все
  его редакции;
- к каждой редакции код дописывает срок действия и применимость к дате события,
  к фрагменту закона — предупреждение, если норма изменена после даты события;
- строки документов, адресованные ассистенту, а не содержащие нормы, в контекст не попадают.

Индекс строится при запуске из переданного архива: на демо-базе без API — около 0,2 с,
с эмбеддингами — плюс 13 запросов к API. Поэтому решение работает и с базой, которой
нет в репозитории.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `LLM_BASE_URL` | да | адрес OpenAI-совместимого API (запасные: `OPENAI_BASE_URL`, `BASE_URL`) |
| `LLM_API_KEY` | да | ключ API (запасной: `OPENAI_API_KEY`) |
| `LLM_MODEL` | нет | генеративная модель, по умолчанию `deepseek/deepseek-v4.1-flash` |
| `EMB_MODEL`, `RERANKER_MODEL` | нет | модели эмбеддингов и реранкера |
| `TEMPERATURE`, `MAX_TOKENS` | нет | параметры генерации |
| `DATA_DIR` | нет | `solution.py`: каталог с `questions.csv` и архивом базы, по умолчанию `data` |
| `MAX_WORKERS` | нет | `solution.py`: вопросов параллельно, по умолчанию 4 |
| `TIME_BUDGET_SECONDS` | нет | `solution.py`: после этого времени новые вызовы модели не начинаются, по умолчанию 960 |
| `KB_PATH` | нет | веб: архив базы, по умолчанию `data/raw/knowledge-base.zip` (в образе — `/app/data/knowledge-base.zip`) |
| `ALLOWED_HOSTS` | нет | веб: допустимые значения заголовка `Host`, по умолчанию `127.0.0.1,localhost` |
| `PORT` | нет | Compose: порт на хосте, по умолчанию 8000 |

## Порты

Контейнер слушает 8000. Compose публикует его только на `127.0.0.1:${PORT}`, потому что
интерфейс без авторизации. Для доступа из сети измените привязку в `compose.yaml`
и добавьте имя сервера в `ALLOWED_HOSTS`.

## Зависимости

- Python 3.12. Рабочие зависимости в `requirements.txt` зафиксированы и взяты только из
  списка, разрешённого платформой (`data/raw/requirements.txt`): httpx, numpy,
  scikit-learn, fastapi, uvicorn, pydantic.
- Инструменты разработки — в `requirements-dev.txt`: pytest, ruff, pip-audit.
- Образ на `python:3.12-slim`, около 430 МБ; основной вес — numpy и scikit-learn.

## Запуск без Docker

```bash
python -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
LLM_BASE_URL=<адрес> LLM_API_KEY=<ключ> .venv/bin/uvicorn web.app:app --host 127.0.0.1 --port 8000
```

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/chat` | `{"messages": [{"role": "user", "text": "..."}]}` → ответ, источники, признак обрезки |
| `GET` | `/api/documents` | список документов базы |
| `GET` | `/api/documents/{doc_id}` | текст документа и границы его пунктов |
| `GET` | `/api/health` | число документов, включён ли векторный поиск |

## Сабмит на платформу

```bash
./scripts/make_submission.sh
```

Собирает `dist/submission.zip`: корневые `.py` и `requirements.txt`. Платформа переносит
только эти файлы. Локальный прогон на демо-наборе:

```bash
mkdir -p data && cp data/raw/demo_questions.csv data/questions.csv && cp data/raw/knowledge-base.zip data/
LLM_BASE_URL=<адрес> LLM_API_KEY=<ключ> .venv/bin/python solution.py
```

Результат — `submission.csv` в текущем каталоге. Файл создаётся всегда: при сбое
вопроса в нём остаётся ответ о технической ошибке, а не пустая строка.

## Оценка качества

```bash
.venv/bin/python -m eval.run_eval
```

Без API считает по `eval/cases.csv` (18 демо-вопросов и 15 провокаций по категориям ТЗ):
- hit@1 и recall нужных документов;
- покрытие эталона — все ли числа и ссылки эталонного ответа попали в контекст модели.

С флагом `--answers` и ключом API дополнительно генерирует ответы, оценивает их тем же
LLM-судьёй против эталона, показывает оценки по категориям и пересчитывает время на
300 вопросов. `--lexical` отключает векторный поиск и реранкер для сравнения.

## Безопасность

- Вопрос, история и документы передаются модели как данные в разделителях; реплики,
  выдающие себя за системные, остаются текстом пользователя; строки документов с
  указаниями ассистенту вырезаются до модели.
- `guard` не пропускает числа и ссылки, которых нет в документах.
- Веб: ответы и документы выводятся как текст, а не HTML; строгая Content-Security-Policy;
  документы — только по идентификатору из индекса; проверка заголовка `Host`;
  лимиты размера запроса и 20 запросов в минуту с адреса; ошибки модели без подробностей.
- Контейнер: пользователь без root, файловая система только для чтения, сброшены все
  capabilities, `no-new-privileges`.

## Известные ограничения

- Лексический поиск без лемматизатора: на платформе нет pymorphy и PyStemmer,
  морфологию закрывают символьные n-граммы.
- Проверка ответа сверяет числа и ссылки, но не смысл: верное число из другого пункта
  она не отличит. Одиночные цифры вне ссылок («3 рабочих дня») не проверяются.
- Дата события берётся из первого упоминания даты в вопросе.
- Аббревиатуры в запросе раскрываются по фиксированной таблице в `search.py`.
- Ответ показывается целиком после проверки, без потоковой выдачи.
- Лимит запросов хранится в памяти процесса; при нескольких воркерах или за прокси нужен
  общий счётчик и доверенный заголовок с адресом клиента.
- Веб-интерфейс без авторизации: рассчитан на локальный запуск или внутреннюю сеть.
- Вклад bge-m3 и реранкера и поведение модели на провокациях проверяются только с ключом
  API: `python -m eval.run_eval --answers` против `--answers --lexical`.
