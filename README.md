# Юридический ассистент ПСБ

Решение кейса ПСБ на Hack&Change 2026. Ассистент отвечает юристам на вопросы по базе
нормативных документов: законам, договорам и внутренним регламентам. Каждый вывод
подтверждается ссылкой на пункт документа. Если в базе нет данных, ассистент так и
говорит.

План работ и принятые решения: [PLAN.md](PLAN.md).

## Состояние

Готовы этапы 1–4: конвейер для автоматической проверки на платформе, гибридный поиск,
контроль достоверности, стенд оценки и веб-интерфейс. Docker появится на этапе 5.

## Как устроено

| Модуль | Назначение |
|---|---|
| `solution.py` | точка входа платформы: `questions.csv` + `knowledge-base.zip` → `submission.csv` |
| `kb.py` | чтение архива (txt, md, docx), разбор на пункты договоров и законов со смещениями в тексте |
| `dialog.py` | разбор истории диалога из текста вопроса (`Пользователь:` / `Ассистент:`) |
| `search.py` | гибридный поиск: TF-IDF по символьным n-граммам + bge-m3, слияние RRF, реранкер; сборка контекста |
| `relations.py` | связи документов: доп. соглашение ↔ договор, редакции одного регламента |
| `dates.py` | дата события из вопроса; срок действия редакций; изменения норм после даты события |
| `guard.py` | проверка ответа: числа, пункты, статьи и номера законов должны быть в переданных модели текстах |
| `prompts.py` | системная инструкция, пометки о редакциях, сборка сообщений |
| `answer.py` | вопрос → ответ с проверкой и одним повтором; общий для проверки и веб-интерфейса |
| `citations.py` | какие документы и пункты цитирует ответ — для подсветки в интерфейсе |
| `web/app.py`, `web/static/` | HTTP API и чат с просмотром документов |
| `llm.py` | запросы к OpenAI-совместимому API с повторами на 429/5xx/таймаут |
| `config.py` | переменные окружения |

Поток: вопрос → разбор диалога → поиск фрагментов → вызов модели → проверка ответа →
(при нарушении) один повтор с перечнем нарушений → ответ.

Контекст:
- небольшие документы (до 6 000 символов) модель получает целиком, у крупных — найденные
  пункты и оглавление статьи (начало каждого пункта);
- вместе с договором идут его дополнительные соглашения, вместе с регламентом — все его редакции;
- к каждой редакции код дописывает срок действия и применимость к дате события из вопроса,
  к фрагменту закона — предупреждение, если норма изменена после даты события;
- строки документов, адресованные ассистенту, а не содержащие нормы, в контекст не попадают.

Если после повтора в ответе остаются данные, которых нет в источниках, предложения с ними
удаляются; если не остаётся ничего, ассистент сообщает, что данных недостаточно.

Если API эмбеддингов или реранкера недоступен, поиск продолжает работать на TF-IDF.

## Запуск

Нужен Python 3.12.

```bash
python -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
```

Прогон на демо-наборе:

```bash
mkdir -p data && cp data/raw/demo_questions.csv data/questions.csv && cp data/raw/knowledge-base.zip data/
LLM_BASE_URL=<адрес API> LLM_API_KEY=<ключ> LLM_MODEL=<модель> .venv/bin/python solution.py
```

Результат пишется в `submission.csv` в текущем каталоге.

### Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `LLM_BASE_URL` | да | адрес OpenAI-совместимого API (запасные: `OPENAI_BASE_URL`, `BASE_URL`) |
| `LLM_API_KEY` | да | ключ API (запасной: `OPENAI_API_KEY`) |
| `LLM_MODEL` | нет | генеративная модель, по умолчанию `deepseek/deepseek-v4.1-flash` |
| `DATA_DIR` | нет | каталог с `questions.csv` и архивом базы, по умолчанию `data` |
| `MAX_WORKERS` | нет | число вопросов, обрабатываемых параллельно, по умолчанию 4 |
| `TEMPERATURE`, `MAX_TOKENS` | нет | параметры генерации |
| `EMB_MODEL`, `RERANKER_MODEL` | нет | модели эмбеддингов и реранкера, по умолчанию `baai/bge-m3`, `qwen/qwen3-reranker-8b` |
| `TIME_BUDGET_SECONDS` | нет | после этого времени новые вызовы модели не начинаются, по умолчанию 960 |
| `KB_PATH` | нет | архив базы знаний для веб-интерфейса, по умолчанию `data/raw/knowledge-base.zip` |
| `ALLOWED_HOSTS` | нет | допустимые значения заголовка `Host` через запятую, по умолчанию `127.0.0.1,localhost` |

Ключи передаются только через окружение. В коде и репозитории их нет.

## Веб-интерфейс

```bash
LLM_BASE_URL=<адрес API> LLM_API_KEY=<ключ> .venv/bin/uvicorn web.app:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. Слева — чат, справа — просмотр документа. Под ответом
показаны документы, на которые он ссылается; клик открывает документ и выделяет
процитированные пункты. Остальные документы, которые видела модель, — в списке
«Также просмотрено». Любой документ базы можно открыть из выпадающего списка.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/chat` | `{"messages": [{"role": "user", "text": "..."}]}` → ответ, источники, признак обрезки |
| `GET` | `/api/documents` | список документов базы |
| `GET` | `/api/documents/{doc_id}` | текст документа и границы его пунктов |
| `GET` | `/api/health` | число документов, включён ли векторный поиск |

Защита:
- до 20 реплик; вопрос до 4000 символов, реплика ассистента до 10 000;
- 20 запросов в минуту с адреса;
- запросы с чужим заголовком `Host` отклоняются — защита от DNS rebinding;
- документы отдаются только по идентификатору из индекса;
- строгая Content-Security-Policy; ответы и документы выводятся как текст, а не HTML;
- история диалога хранится только в браузере.

## Сабмит на платформу

```bash
./scripts/make_submission.sh
```

Скрипт собирает `dist/submission.zip`: корневые `.py` и `requirements.txt`.
Платформа переносит только эти файлы. Зависимости ограничены разрешённым списком
из `data/raw/requirements.txt`.

## Оценка качества

```bash
.venv/bin/python -m eval.run_eval
```

Без API считает hit@1 и recall нужных документов и покрытие эталона — все ли числа
и ссылки эталонного ответа есть в контексте модели. В `eval/cases.csv` 18 демо-вопросов
и 15 провокаций по категориям ТЗ. С флагом
`--answers` и заданными `LLM_BASE_URL`/`LLM_API_KEY` дополнительно генерирует ответы,
оценивает их тем же LLM-судьёй против эталона и пересчитывает время на 300 вопросов.
`--lexical` отключает векторный поиск и реранкер для сравнения. Результаты
сохраняются в `eval/results/`.

## Известные ограничения

- Лексический поиск без лемматизатора: на платформе нет pymorphy и PyStemmer,
  морфологию закрывают символьные n-граммы.
- Проверка ответа сверяет числа и ссылки, но не смысл: верное число из другого пункта
  она не отличит. Одиночные цифры вне ссылок («3 рабочих дня») не проверяются.
- Дата события берётся из первого упоминания даты в вопросе.
- Аббревиатуры в запросе раскрываются по фиксированной таблице в `search.py`.
- Ответ показывается целиком после проверки, без потоковой выдачи: потоковый текст
  пришлось бы показывать до проверки на выдуманные факты.
- Лимит запросов хранится в памяти процесса: при нескольких воркерах или за прокси нужен
  общий счётчик и доверенный заголовок с адресом клиента.
- Веб-интерфейс без авторизации: рассчитан на запуск во внутренней сети или локально.
